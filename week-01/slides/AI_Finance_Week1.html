Core motivation

Why must it be a blockchain? Start with "default"

Human ↔ Human

  • Don't repay a loan → sue in court
  • Backed by police, enforcement, credit score
  • A whole institutional system backstops it

Agent ↔ Agent

  • No court hears a machine's case
  • No police; an agent has no body to jail
  • Rules can only be enforced by code itself
In a machine economy, "law" must become "code" — written as a smart contract that auto-liquidates and auto-seizes collateral on time. The place that carries it and everyone agrees on is the blockchain.

Big picture · why this course exists

When AI turns from a "tool" into an "autonomous economic actor"

  • Agents need to hold assets, pay each other, and act with no human watching.
  • Human banking (KYC, business hours, layered intermediary settlement) simply doesn't fit machines.
  • Public chains are the native substrate for machine-to-machine finance: programmable, permissionless, 24/7.
  • The micropayment gap: an AI wants to pay another AI $0.001 — how, with a credit card?It can't — no account, no business hours, no card transaction that small.
This course teaches you to operate here — and to build the agents that will live here.

Part 0 · ①

A blockchain = an objective, public ledger that changes only by the rules

  • It is not a company's database (a company can secretly edit that).
  • It's a state snapshot the whole network agrees on, anyone can read, updated only by fixed rules.
  • "How much you own, what's locked in this contract" is an objective fact anyone can independently verify.
  • This is the bedrock: agents can do business without trust precisely because the ledger is objective and the rules are public and auto-enforced.

Part 0 · ③

A smart contract = "that piece of code living at an address"

  • Because Ethereum is an account + code model, you can write "lending terms" or "swap rules" as a program deployed at an address.
  • Anyone can call it, it runs exactly as written, and no one can change the result mid-way.
  • The "law becomes code" from the last slide — technically, this is it.
Mental model: a vending machine made of math — put in the right input, get the guaranteed output, and not even the owner can reach in mid-purchase and change it. (Part 5 shows a clickable demo.)

Part 2 · with code/gen_wallet.py

A wallet is really just a keypair

private key ──(one-way math)──▶ public key ──(hash)──▶ address 0x02D3…
  • Private key: a huge secret number. Whoever holds it controls the money. Never share it.
  • Address: derived from the key, public — others use it to pay you.
  • Analogy: the address is your mailbox (anyone can drop mail in); the private key is the only key that opens it. Lose it = locked forever. There is no "forgot password".
In class: everyone generates a pair and pastes only the address into chat. "Nobody's tempted to paste the private key to show off — you instinctively know what it protects." (Throwaway practice key — never real money.)

Part 3

A transaction = one signed message

{ from, to, value, data, nonce } + your signature (r, s, v)
  • The network recovers your address from the signature — proving it's you — while you never expose your private key.
  • The nonce (a counter) stops the same signed message from being replayed twice.
"Sign an intent, the network verifies and executes" is the backbone of everything in this course — the same shape as an agent placing an order or authorizing a payment (Weeks 5 & 6).

Key takeaways

Walk away with these five

  • A wallet = a keypair; the private key is everything; the address is public.
  • A transaction = a signed intent; the network verifies by recovering the address from the signature.
  • Gas pays for computation; cheap L2s are what make agent-scale micropayments possible.
  • A smart contract is public, unstoppable code living at an address; composability is both a superpower and a risk.
  • Next session: stablecoins + AMM (x·y=k) — anyone can swap, at the cost of slippage.
